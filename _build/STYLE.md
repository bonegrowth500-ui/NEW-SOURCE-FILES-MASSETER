# STYLE — House rules for every module

## Voice (Blend)
- Second person, operator-to-operator ("you"). Calm authority with conviction; direct, never hypey.
- S+-style reasoning: explain *why* before *what*; every recommendation carries its reasoning.
- Scannable structure on top: clear `##`/`###` headers, bolded named frameworks, bullets for variants/options, tables where comparison is the point, short paragraphs (2–5 sentences). No walls of text; no bullet-only skeletons either.
- Plain language; niche vocabulary used correctly and defined once in-module when first used.
- Theory + application: name the psychological/economic mechanism, then show exactly how it's used in this niche.

## Niche grounding
- Every module is about a facial-development & bone-growth coaching business. Examples, scenarios, scripts, numbers are all niche-specific (mewing stalls, recessed chin worries, mouth-breathing, adult-change skepticism, grift fatigue, etc.).
- Never teach the techniques themselves (tongue posture how-to, protocols). The method is assumed; only its packaging may appear.

## Named frameworks
- Frameworks get memorable, distinct names (Title Case, bolded on first use). Each is registered in `_build/REGISTRY.md` → becomes the Glossary.
- Present frameworks as **options + default pick** where a choice exists: variants with reasoning for when to pick each, then the recommended default.

## Numbers
- Ranges with context, always: "typically X–Y; higher when…, lower when…". No false precision, no invented single-point stats. Keep ranges consistent with `_build/LEDGER.md`.

## Module template (Hybrid) — finalized in Step 2.6
1. Title + one-paragraph opening frame (what this module changes in how you think/operate).
2. Deep sections (numbered `##` sections), each: mechanism → reasoning → application in the niche.
3. Named frameworks with variants + default pick.
4. Worked example(s): realistic composite niche cases walked end-to-end.
5. Extras (chosen per module): scripts & swipe copy (persuasion/sales/content modules), checklists/templates (business/ops modules), action steps (all modules).
6. **Stage Notes**: Early / Growing / Scaling — what changes at each stage.
7. **Standard Check** (brief): how the module's tactics sit against the Standard Card.
8. **Quick Reference**: summary, key takeaways, framework cheat sheet.

## Hard rules
- Never mention the source files or any "prior program". No "as you learned".
- Cross-references to other modules of this blueprint are allowed ("see Module 9"), sparingly.
- Exclusions (faceless strategy, launch campaigns, operator mindset/self-help, podcasts & collabs, techniques/protocols, free community) never appear as recommendations.
- AI tools and legal/risk: minimal mentions only.
- ~7,000 words (6,300–7,700).
